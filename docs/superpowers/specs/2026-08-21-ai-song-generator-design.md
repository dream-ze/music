# AI 歌词成曲 Demo — 设计文档

- 日期：2026-08-21
- 状态：设计已确认，待写实现计划

## 1. 目标

一个网页 demo：用户输入**歌词**和**风格描述**，系统自动**作曲 + 编曲 + 演唱**，产出一首完整的中文歌曲；并可选地把人声**音色转换**成指定的目标嗓音（音色克隆）。全部基于开源模型自建，不依赖商业 API。

### 成功标准
- 输入一段中文歌词 + 一句风格描述（如"周杰伦风格的中国风 R&B"），能在几分钟内生成一首可试听的完整歌曲（含人声与伴奏）。
- 可选启用音色转换：把生成的人声换成一个预置的示例目标音色，结果可在网页试听并下载。
- 整条链路在 Colab（免费 T4/低成本 GPU）上能跑通。

## 2. 关键决策（已确认）

| 维度 | 决定 |
|---|---|
| 路线 | 开源自建 |
| 算力 | 云 GPU（先 Colab 起步，后续可迁 Runpod/AutoDL） |
| 风格控制 | 文字风格描述 + 音色克隆（RVC） |
| 语言 | 中文为主 |
| 交互 | Gradio 网页 |
| 生成粒度 | 端到端出歌 + 音色转换 |
| 音色素材 | demo 阶段用**示例占位音色**；上传训练作为后续扩展 |

## 3. 架构与数据流

```
歌词 + 风格标签
   │  ① ACE-Step   端到端生成整首歌（旋律 + 编曲 + 人声）
   ▼
整首歌（混音 wav）
   │  ② Demucs v4  分离人声轨 / 伴奏轨
   ▼
人声轨 ──③ RVC──▶ 换成目标音色（示例占位模型）──┐
伴奏轨 ──────────────────────────────────────────┤ ④ 混音（对齐 + 增益 + 导出）
                                                  ▼
                                              成品歌曲 wav
```

- **音色转换是 4 步链路，不是 1 步**：端到端模型输出的是混好的整首歌，必须先分离出人声，才能对人声单独做音色转换，再与原伴奏混回。
- **中文由 ① 保证**：咬字发音来自 ACE-Step 的中文人声；③ RVC 只换音色、对语言不敏感。

### 离线准备（一次性，非 demo 主链路）
训练 RVC 目标音色模型：`纯人声素材(≥10min) → 切片+重采样 → 提取 F0 + HuBERT 特征 → 训练 → 得到 音色.pth + 检索.index`。不需要歌词/标注（自监督）。demo 首版直接用**社区现成的示例音色模型**占位，此步作为后续入口。

## 4. 模型选型

| 环节 | 首选 | 备选 | 理由 |
|---|---|---|---|
| 端到端出歌 | ACE-Step（Apache 2.0，多语言，~15GB 显存，快） | YuE（质量更高但重/慢）、DiffRhythm（极快） | 中文支持较好、许可宽松、显存友好 |
| 人声/伴奏分离 | Demucs v4 (htdemucs) | UVR5 | 成熟稳定、易集成 |
| 音色转换 | RVC (RVC-Project WebUI) | So-VITS-SVC（质量略高、训练更重） | 训练快、社区大、demo 足够 |
| 前端 | Gradio | — | 与 Python 模型链路无缝，支持 share 链接 |

## 5. 组件划分（各自单一职责、接口清晰、可独立测试）

- **`song_gen`** — 封装 ACE-Step。输入 `(lyrics, style_prompt, 时长/seed 等参数)`，输出整首歌 wav 路径。
- **`separator`** — 封装 Demucs。输入混音 wav，输出 `(vocal_wav, instrumental_wav)`。
- **`voice_convert`** — 封装 RVC 推理。输入 `(vocal_wav, 音色模型路径, index 路径, 变调等参数)`，输出转换后人声 wav。
- **`mixer`** — 人声 + 伴奏对齐混音、增益、导出成品。输入两轨，输出 final wav。
- **`pipeline`** — 编排 ①→②→③→④，把上述组件串起来；音色转换可开关。
- **`app`** — Gradio UI：歌词输入框、风格描述框、参数、"是否启用音色转换"开关与音色选择、生成按钮、各阶段中间结果试听、成品下载。

每个组件对外暴露纯函数式接口（输入路径/参数 → 输出路径），便于在无 UI 情况下单测。

## 6. 错误处理

- **显存不足 (OOM)**：捕获后在 UI 明确提示"降低时长/换更小模型/升级 GPU"，不静默失败。
- **模型/权重缺失**：启动时检查权重文件，缺失则给出下载指引，不在生成时才报错。
- **人声分离质量差 → 音色转换劣化**：允许用户跳过音色转换、直接用端到端原版人声。
- **各阶段产物落盘**：每步中间结果（整首歌、人声轨、伴奏轨、转换后人声）都保存并在 UI 可试听，任一步出问题可定位。

## 7. 测试策略

- **组件级**：每个封装模块用一小段固定输入音频/短歌词跑 smoke test，断言输出文件存在、时长/采样率合理。
- **链路级**：一条最短歌词端到端跑通，产出成品且各中间产物齐全。
- **手动验收**：在 Gradio 里输入真实中文歌词 + 风格，主观试听质量。

## 8. 明确不做（YAGNI）

- 不做分阶段可控作曲（MIDI 旋律→逐轨编曲→DiffSinger 逐字合成）——太重、质量不占优。
- 首版不做"上传素材在线训练音色"，只留入口；训练走离线脚本/后续迭代。
- 不做账号、存储、分享社区等产品化功能。
- 不做本地 Mac 跑重模型（硬约束：需 CUDA）。

## 9. 部署路线

1. **Colab 起步**：Notebook 装依赖 + 拉权重，`app.py` 用 `gradio share` 出公网链接，零成本验证整条链路。
2. **迁移 Runpod/AutoDL**：代码写成环境无关（路径/设备可配置），效果确认后迁到常驻 GPU 做稳定演示。
