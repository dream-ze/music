# 多供应商文本模型设计

## 目标

让用户在 Gradio 网页的高级设置中选择文本模型供应商，而不是在代码中固定使用 Anthropic。首期支持 DeepSeek、OpenAI、通义千问、Gemini、Anthropic 和本地 Ollama。文本模型仍只负责歌曲规划与歌词结构化，ACE-Step 继续负责本地成曲。

## 用户体验

高级设置新增以下控件：

- 模型供应商下拉框：DeepSeek、OpenAI、通义千问、Gemini、Anthropic、Ollama。
- 模型名称输入框：切换供应商时填入推荐默认值，用户可以覆盖。
- API Key 密码框：不回显已保存的完整 Key。
- “保存 Key”按钮：将当前供应商的 Key 保存到 Windows 凭据管理器。
- “删除 Key”按钮：删除当前供应商已保存的 Key。
- 配置状态：仅显示当前供应商的 Key 是否已配置。
- 模型调用状态：显示调用成功，或显示已经回退及简短原因。

Key 输入一次并保存后，后续启动自动读取，不需要重复粘贴。Ollama 不需要 Key，默认服务地址为 `http://127.0.0.1:11434`。

## 供应商与默认配置

| 供应商 | 默认模型 | Key 环境变量 | 接口方式 |
|---|---|---|---|
| DeepSeek | `deepseek-v4-flash` | `DEEPSEEK_API_KEY` | OpenAI 兼容接口 |
| OpenAI | `gpt-5-nano` | `OPENAI_API_KEY` | OpenAI 兼容接口 |
| 通义千问 | `qwen-flash` | `DASHSCOPE_API_KEY` | OpenAI 兼容接口 |
| Gemini | `gemini-2.5-flash` | `GEMINI_API_KEY` | Gemini 官方接口 |
| Anthropic | `config.LLM_MODEL` | `ANTHROPIC_API_KEY` | Anthropic 官方接口 |
| Ollama | `qwen2.5:3b` | 无 | 本地 HTTP 接口 |

具体默认模型集中放在配置表中，避免散落在界面和客户端实现里；用户始终可以在界面覆盖模型名。

## 架构

### 统一请求契约

`src/llm.py` 对业务层继续暴露返回字符串的 `complete()` 入口，但增加供应商、模型和临时 Key 参数。它把请求交给供应商适配器；失败时抛出不含秘密信息的统一异常。

`planner` 和 `lyrics` 只使用统一契约，不直接导入任何供应商 SDK。流水线把同一份模型配置和一个状态事件列表传给两次文本调用，确保歌曲规划和歌词结构化使用同一供应商；两个阶段分别向列表追加成功或回退状态，最后由流水线返回给界面。现有函数未提供模型配置时继续按默认参数工作。

### 供应商适配器

- DeepSeek、OpenAI、通义千问共用 OpenAI 兼容客户端逻辑，通过不同 Base URL、模型名和 Key 区分。
- Anthropic 使用现有官方 SDK 调用。
- Gemini 使用官方 HTTP/SDK 接口，封装在适配器内。
- Ollama 使用本地 HTTP 接口，不要求 API Key。

所有适配器统一处理超时、空响应和可安全展示的错误。任何日志与错误信息都不得包含 Key。

### Key 存储

新增独立凭据模块，使用 Windows 凭据管理器，并按应用名和供应商分别保存。读取优先级为：

1. 当前界面本次输入的临时 Key；
2. Windows 凭据管理器中保存的 Key；
3. 对应环境变量。

凭据模块只提供保存、读取、删除和是否存在四种操作。测试通过替换凭据后端完成，不读取或修改开发者的真实凭据。

## 数据流

1. 用户选择供应商，可覆盖模型名，并输入或复用已保存的 Key。
2. 界面构造不含持久化秘密的模型配置，传给歌曲流水线。
3. 规划器调用统一 LLM 路由器生成 `SongSpec`。
4. 歌词模块通过同一配置生成结构化歌词。
5. ACE-Step 根据结果生成音频。
6. 页面显示音频、结构化歌词和模型调用状态。

## 回退与错误处理

- 云供应商缺少 Key、请求超时、认证失败、网络错误、响应为空或格式非法时，不阻断歌曲生成。
- 规划器回退到安全默认 `SongSpec`，歌词模块回退到本地简单分段。
- 页面必须明确显示“已回退”，并给出不包含秘密信息的简短原因。
- Ollama 未运行或模型不存在时使用相同回退机制。
- Key 保存或删除失败只影响凭据操作，必须给出明确提示，不能误报为已保存。
- ACE-Step 自身的成曲失败不属于文本模型回退范围，仍按生成错误显示。

## 兼容性

- 保留现有 `ANTHROPIC_API_KEY` 和 `LLM_MODEL` 使用方式。
- 未从界面提供新配置的旧调用继续使用默认供应商配置。
- Gradio 页面保持主输入区简洁，所有模型配置放在高级设置内。
- 仅 Windows 支持凭据持久化；非 Windows 环境仍可使用临时 Key 或环境变量，保存按钮返回平台不支持提示。

## 测试

- 路由测试：每个供应商映射到正确适配器、Base URL、Key 名和默认模型。
- Key 优先级测试：临时输入覆盖凭据，凭据覆盖环境变量。
- 凭据测试：保存、读取、删除、平台不支持和后端异常。
- 响应测试：正常文本、空响应、认证失败、超时，且异常信息不泄露 Key。
- 流水线测试：供应商和模型配置贯穿规划器与歌词模块。
- 回退测试：缺 Key 或调用异常仍会进入 ACE-Step，并向界面返回回退状态。
- UI 绑定测试：新控件参数正确传入生成回调，Key 字段使用密码类型。
- 全量回归：现有测试继续通过，并做一次页面启动健康检查。

## 非目标

- 不在本次实现账户登录、云端同步或跨 Windows 用户共享 Key。
- 不保存完整对话或模型响应历史。
- 不为每个供应商暴露温度、Top-P 等专业参数。
- 不改变 ACE-Step 模型、音频生成参数或主界面工作流。
